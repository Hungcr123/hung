## Permanent Lesson Vault Structure/Progress Semantics - DO NOT COMPACT OR REMOVE

This section is a permanent coding contract. When compacting `AGENTS.md`, preserve it verbatim and do not replace it with a shorter summary. Structural chips are global file metadata, never user progress: calculate once from lesson content, persist in the shared Server Data manifest/SQLite document, preload into frontend RAM for every user, and recalculate only the changed/rebuilt file plus its affected folder totals. A normal Lesson Vault/tree read must never decode lesson files, rescan folders, or calculate these counts per user.

- Space_V/Space_B: `Nodes` means vocabulary word records in the file. Current-run progress is learned words in the newest identified `runId` divided by that run's word total. `Learned`/`Completed` is lifetime history and must remain true after a later New Study resets current progress to `0/N`.
- Space_W: `Nodes` means root translation nodes. `Normal` equals the valid root-node count. `Train` is calculated per root: use its valid explicit extra-practice/train entries when present, otherwise one fallback train sentence for that root. `Sentences = Normal + Train`. Runtime progress is dynamic: normal root pass plus shuffled review pass, and enabling Train can expand the workload/denominator. Never replace the newest active run with a higher percentage from lifetime completion history.
- Space_P/Space_L/Space_S: these three share the paragraph payload structure. `Paragraphs` means the number of large/root paragraph nodes. `Nodes` means the sum of all child sentence nodes across every paragraph; if an old payload has no child arrays, fall back to the root-node count. Progress uses the child-sentence workload, while the Paragraph chip remains structural information only.
- Space_Q: keep root-node count and recursive question count separate. When a valid question count exists, question progress uses it as the denominator; otherwise fall back to root nodes. Do not infer either value from a user's saved progress when file metadata is available.
- Space_PDF: structural `Nodes` means total PDF pages and is read once from the PDF document, then cached by file `mtime_ns + size`. Current page, completed/page progress, pinned pages, drawings, and lifetime completion are separate persisted states; pinned-page timestamps use numeric epoch ordering.
- Space_Picture: do not invent a node total from progress. Only expose a structural count when the file/region format has an authoritative count; otherwise keep it zero and preserve image/PDF progress state independently.

- Shared cache/CPU rule: Server 2 startup warms the compact tree base before accepting learners and may warm gzip tree responses for registered users. Tree preload carries structural fields (`nodes`, `questions`, `paragraphs`, `sentences`, `normal_sentences`, `train_sentences`) and frontend chips read them directly from RAM even for never-studied files. Native watcher delta refresh must reuse unchanged entry metadata and decode only the changed file.
