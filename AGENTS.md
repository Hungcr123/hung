## Time Sync Gate

- Treat timestamp, revision, freshness, merge, cache, WAL, progress, and cross-device ordering bugs as high severity.
- Never compare timestamp strings directly; convert client ISO UTC, local server time, offsets, and legacy formats with `timestamp_to_epoch()` or equivalent before ordering.
- For any change that sends, receives, merges, caches, or persists server data, verify client-newer/server-newer ordering, UTC vs local timezone, equal timestamps, missing/legacy timestamps, stale-device overwrite protection, and restart/WAL replay.

- Do not report completion from syntax checks alone. If a check was not run, mark the task blocked or incomplete.
- After every completed task that updates Server 2, reads server data, changes caching, or changes persistence, append a dated incident/evidence entry to this file.

## Server 2 Contracts

- PostgreSQL is the only database for mutable server state, settings, documents, user state, collision/quarantine metadata, and all QM-City state. Do not create, read, write, migrate to, or fall back to SQLite or local database files for runtime state.
- All new mutable fields (skills, loadouts, HP, mana, cooldowns, positions, inventory, and combat events) must use PostgreSQL repositories/transactions with per-user delta writes, idempotency keys, and bounded/coalesced writes.
- `initialize_server_database()` must return cached `SERVER_DATABASE_READY_STATUS`; do not run schema checks, full counts, or document rewrites on each user action.
- Any later historical evidence below that mentions SQLite describes retired/migration state only; it is not an allowed implementation path. New code and all production runtime paths must remain PostgreSQL-only.
- Offline learning uses the per-user durable client outbox. Merge by numeric time and run identity: newest valid checkpoint wins, stale devices cannot overwrite it, clear/delete cannot be resurrected, and older completion history is preserved separately.
- Completion uses durable intents/events and startup recovery.
- Login preload is authenticated and contains only the signed-in user's mutable state. Lesson Vault tree preload is separate authenticated compact-v1 snapshot with ETag/304 and gzip caching. Unauthenticated access is 401; cross-user access is 403.
- Normal Lesson Vault navigation trusts frontend RAM/local cache/login preload. Repeated breadcrumb/folder clicks must not call `/server-data/list`, `/lesson-tasks`, or `/server-data/last-file` when owner/path and cached tree are unchanged.
- Server startup loads the manifest, constructs the shared compact tree base, and warms gzip tree responses for registered users before HTTP listens.
- Use one native `ReadDirectoryChangesW` watcher for Server Data. Debounce and delta-refresh only affected branches/files.
- Structural metadata is keyed by file `mtime_ns + size` plus dependency signature. Rebuild/decode only the changed lesson file.
- Sound assets use `future_sound_asset_index.py`, `_future_sound_asset_index.json` plus WAL, and sharded `Sound/_v2/...` writes.
- STT, voice, process workers, and Cloudflare Tunnel are detached/reused across soft Server 2 restarts.
- Shared write-behind state must use one bounded/coalesced worker or timer, never one polling loop/thread/timer per user.

- PostgreSQL remains authoritative for mutable user state and collision/quarantine metadata. Location/alias/replica tables and manifests must be rebuildable, optional, and not required to reconnect progress.
- Copy means same logical lesson and shared progress. Only **Duplicate as New Lesson** may rewrite the embedded ID.

- Builders, imports, migrations, PDF/Picture conversion, and automatic Space creation must use the same identity allocator/finalizer.
- Each physical Space/package contains exactly one lesson ID; per-user child state remains PostgreSQL-keyed by `(user_id, lesson_id, child_key...)`.
- Generic open validates once and returns an authenticated, revision-bound lesson descriptor/opaque handle; later calls use `lesson_id + handle`.

- Space_W `Continue Previous` resumes the saved checkpoint; `Review Train` is separate. Progress denominator is dynamic.

## Permanent Lesson Vault Structure/Progress Semantics - DO NOT COMPACT OR REMOVE

This section is a permanent coding contract. When compacting `AGENTS.md`, preserve it verbatim and do not replace it with a shorter summary. Structural chips are global file metadata, never user progress: calculate once from lesson content, persist in the shared Server Data manifest/PostgreSQL document, preload into frontend RAM for every user, and recalculate only the changed/rebuilt file plus its affected folder totals. A normal Lesson Vault/tree read must never decode lesson files, rescan folders, or calculate these counts per user.

- Space_V/Space_B: `Nodes` means vocabulary word records in the file. Current-run progress is learned words in the newest identified `runId` divided by that run's word total. `Learned`/`Completed` is lifetime history and must remain true after a later New Study resets current progress to `0/N`.
- Space_W: `Nodes` means root translation nodes. `Normal` equals the valid root-node count. `Train` is calculated per root: use its valid explicit extra-practice/train entries when present, otherwise one fallback train sentence for that root. `Sentences = Normal + Train`. Runtime progress is dynamic: normal root pass plus shuffled review pass, and enabling Train can expand the workload/denominator. Never replace the newest active run with a higher percentage from lifetime completion history.
- Space_P/Space_L/Space_S: these three share the paragraph payload structure. `Paragraphs` means the number of large/root paragraph nodes. `Nodes` means the sum of all child sentence nodes across every paragraph; if an old payload has no child arrays, fall back to the root-node count. Progress uses the child-sentence workload, while the Paragraph chip remains structural information only.
- Space_Q: keep root-node count and recursive question count separate. When a valid question count exists, question progress uses it as the denominator; otherwise fall back to root nodes. Do not infer either value from a user's saved progress when file metadata is available.
- Space_PDF: structural `Nodes` means total PDF pages and is read once from the PDF document, then cached by file `mtime_ns + size`. Current page, completed/page progress, pinned pages, drawings, and lifetime completion are separate persisted states; pinned-page timestamps use numeric epoch ordering.
- Space_Picture: do not invent a node total from progress. Only expose a structural count when the file/region format has an authoritative count; otherwise keep it zero and preserve image/PDF progress state independently.

- Shared cache/CPU rule: Server 2 startup warms the compact tree base before accepting learners and may warm gzip tree responses for registered users. Tree preload carries structural fields (`nodes`, `questions`, `paragraphs`, `sentences`, `normal_sentences`, `train_sentences`) and frontend chips read them directly from RAM even for never-studied files. Native watcher delta refresh must reuse unchanged entry metadata and decode only the changed file.
